# OpenAI External-Model Validation — Protocol (SEPARATE from the frozen primary protocol)

**This document covers only the separate external-model stress test. It does
not modify, supersede, or append to `../FROZEN_PROTOCOL.md`, which governs
the primary five-model validation and remains unchanged (byte-for-byte
hash-verified before and after this experiment).**

## 1. Scientific Question

Does the frozen five-model reliability framework's `combined_score` — built
and calibrated with zero knowledge of any OpenAI model — correlate with
correctness for predictions generated by an OpenAI model that was never
part of the framework's construction? This is a generalization stress test
of the *score*, not a new benchmark of OpenAI models and not a new primary
endpoint.

## 2. Reused, unmodified inputs

- Held-out protein set: `../scripts/heldout_sample_250.json` (243 accessions, identical)
- Prompts: `../scripts/llm_prompting_heldout.py::build_prompts()`, imported directly (not retyped) — P1–P4 only, byte-identical wording/few-shot examples; P5 does not exist in that module
- GO ontology, evidence-code filter, correctness definition: identical to the frozen primary protocol

## 3. Model

`gpt-5.5-2026-04-23` — selected by the user from 3 options after a live
`/v1/models` query, due to genuine ambiguity in which OpenAI model to use.

## 4. Generation parameters (empirically determined, not invented)

| Parameter | Value | Note |
|---|---|---|
| `max_completion_tokens` | 512 | This model rejects `max_tokens`; renamed parameter, same numeric budget as the frozen experiment |
| `temperature` | not set | This model only supports its default (1); explicit 0.0 is rejected by the API |
| `top_p` | not set | Left at API default |
| `seed` | 42 | Confirmed via probe to produce identical output for an identical prompt |
| system message | none | Matches frozen convention (single user-role message) |

## 5. Calls

243 proteins × 3 namespaces × 4 prompts × 1 model = **2,916 planned calls**.
(The user's initial instruction stated 972; this was flagged as a namespace-multiplication
discrepancy and resolved by explicit user decision to match the frozen convention.)

## 6. Critical methodological finding — reasoning-token budget exhaustion

**2,855 of 2,914 successful calls (98.0%) returned an empty visible
response**, despite `usage.completion_tokens=512` (the full budget consumed).
A targeted diagnostic probe (outside the scientific call set) confirmed the
cause: `finish_reason='length'` with `reasoning_tokens=512/512` — this model
is a reasoning model that spends its completion-token budget on invisible
internal reasoning before emitting visible output. At a much larger budget
(4,000 tokens) in the same probe, the identical prompt succeeded
(`finish_reason='stop'`, `reasoning_tokens=2,527`, visible GO-term output
produced).

**This was discovered only after the full run completed.** Per the
experiment's standing instruction — "if you discover a problem that would
require changing prompts/parameters, STOP and report it instead of adapting
the experiment" — `max_completion_tokens` was **not** increased and the run
was **not** repeated. The 2 hard failures share this exact root cause (not a
transient infrastructure error) and were therefore not retried with
identical parameters.

**Consequence for interpretation:** only 100 distinct GO claims survived
across the entire 2,914-call run. These are not a random sample of the
model's "true" predictions — they are systematically the cases where the
model's internal reasoning happened to be short enough to leave room for
visible output. Any analysis of this surviving set is affected by this
survivorship bias and is reported as exploratory/diagnostic only, not as a
clean confirmatory test of the generalization question.

## 7. No-leakage commitment (honored)

The discovery above was not used to change the reliability score, model
selection, prompts, thresholds, held-out cohort, primary endpoint, or
correctness definition. It is reported as a limitation of this specific
external-model run.

## 8. Frozen-score lookup (read-only reference)

`analysis/frozen_claim_score_lookup_READONLY.json` is a read-only
reconstruction of the frozen 5-model `combined_score` for every
(accession, namespace, go_id) claim, built strictly from the unmodified
`../heldout_results/*.jsonl` files. It is a derived artifact of this
external-validation experiment, not a new version of any frozen file, and
is not referenced by or written back into the primary protocol.
